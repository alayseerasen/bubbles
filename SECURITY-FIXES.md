# Что было исправлено

Аудит + правки от 26.10.2026. Все изменения уже внесены в эту папку —
ниже список того, что было не так и что поменялось.

## 1. XSS (главное)

Данные из базы рендерились через `innerHTML`, часто внутри
`onclick="..."`, без проверки. Через прямой запрос к Supabase API можно
было записать в `id`, `avatar`, `cover`, `image`, `emoji` и т.п.
произвольную строку и выполнить свой JS у других людей (угон сессии).

Что сделано (`js/app.js`):

- Добавлены проверки **на входе**, в мапперах `rowTo*`, через которые
  проходят все данные из БД:
  - `safeId()` — id только `[A-Za-z0-9_-]` (uuid и `uid()` проходят);
  - `safeImageUrl()` / `safeMediaUrl()` — только `http(s)`, относительные
    пути, `blob:` и `data:image` / `data:audio|video`; `javascript:` и
    `data:text/html` отбрасываются; кавычки/пробелы экранируются, уже
    закодированные `%20` при этом не ломаются;
  - `safeEmoji()` — реакции только из не-ASCII символов (обычные эмодзи);
  - `safeFrame()` / `safeTheme()` / `safeCoverEffect()` — косметика
    подписки только из известных id.
- Проверки применены во всех `rowToPost/Comment/User/Message/Story/
  Notification/Music/Friend/Report/...`, а также в realtime-обработчиках.
- `avatarFrameClass()` больше не подставляет значение из БД в `class`
  без проверки; `statusBadgeHtml()` экранирует иконку статуса.
- Фон обложки профиля собирается через `cssImageUrl()` (кавычки и
  обратные слэши экранированы) вместо сырого `url('...')`.
- Картинка в чате дополнительно проверяется при рендере.

## 2. Дружба в обход заявок (БД)

Политика `friendships_insert` разрешала вставить «дружбу» с кем угодно,
просто зная его id — заявка, приватность и блокировки не проверялись.

- Политика теперь требует `auth.uid()` среди участников **и** принятую
  заявку (`friend_requests.status = 'accepted'`) ровно между этими двумя
  людьми.
- `acceptFriendRequest()` переставлен: сначала заявка помечается
  принятой, потом создаётся дружба; при ошибке статус возвращается в
  `pending`.

## 3. Стена и посты (БД)

- `protect_and_validate_post_pin()` теперь запрещает менять
  `author_id`, `wall_owner_id`, `created_at` при редактировании. Раньше
  автор мог перенести пост на чужую/приватную стену или «состарить» его.
- `posts_insert` проверяет стену: писать можно на свою стену, на
  публичную чужую или на стену друга; блокировки учитываются. Плюс
  композер на профиле скрывается, если писать нельзя (вместо ошибки
  при отправке).

## 4. Утечка комментариев/опросов с приватных стен (БД)

Комментарии и опросы читались `using (true)` / `auth.uid() is null`,
поэтому были видны даже там, где сам пост скрыт (стена «только друзья»,
блокировка).

- `comments_select`, `polls_select`, `poll_options_select`,
  `poll_votes_select` теперь требуют, чтобы родительский пост был
  виден по правилам `posts_select`.

## 5. Спам уведомлениями / пушами

- Добавлен `under_notification_rate_limit()` (60 уведомлений в минуту
  на автора) и подключён к `bubbles_notifications_insert`.
- `send-push` больше не публичный: функция требует
  `x-webhook-secret` (или `Authorization: Bearer <secret>`) и **не
  отправляет пуши**, если `WEBHOOK_SECRET` не задан. Инструкция —
  `supabase/functions/send-push/README.md` (файл заодно заменён: там
  лежала копия README от другой функции).

## 6. Мелочи

- `index.html`: `js/app.js?v=25` — чтобы PWA не залипла на старом коде.
- `supabase/functions/send-push/README.md` переписан под эту функцию.

# Что нужно сделать тебе (без этого часть правок не заработает)

1. **Прогнать `supabase.sql`** целиком в SQL Editor (скрипт
   идемпотентный, можно запускать повторно).
2. Задеплоить `send-push` заново:
   `supabase functions deploy send-push --no-verify-jwt`
3. В секреты функции добавить `WEBHOOK_SECRET` (длинная случайная
   строка), а в трёх Database Webhooks — заголовок
   `x-webhook-secret` с тем же значением. Иначе пушей не будет.
4. Выложить обновлённые `index.html` и `js/app.js` на хостинг.

# Что сознательно не менялось

- Анонимное чтение публичных профилей/постов/музыки — это похоже на
  задуманное поведение («маленькая соцсеть», просмотр без входа).
  Приватные стены и блокировки при этом закрыты.
- Достижения (`unlocked_achievements`, `achievement_level`) по-прежнему
  пишет клиент — они косметические; если это станет проблемой, их тоже
  можно закрыть триггером.
