ИСПРАВЛЕНО — "УВЕДОМЛЕНИЯ ВКЛЮЧЕНЫ", НО НИЧЕГО НЕ ПРИХОДИТ

Нашли реальную причину: публичный VAPID-ключ в js/push-config.js (им
браузер создаёт подписку) и ключи, которые в README для Edge Function
предлагалось вставить в секреты Supabase, были ДВУМЯ РАЗНЫМИ парами.
Если по инструкции скопировать оттуда как есть — сервер получает
приватный ключ не от той пары, и КАЖДАЯ попытка отправить пуш молча
проваливается, хотя браузер честно говорит "уведомления включены" —
эта надпись проверяет только то, что подписка создалась локально, а
не то, что сервер способен ею воспользоваться.

Сгенерировал новую согласованную пару и вставил её в оба места —
js/push-config.js и supabase/functions/send-push/README.md. Если уже
разворачивал(а) Edge Function раньше:
1. Обнови js/push-config.js на хостинге (новый публичный ключ).
2. Supabase Dashboard → Edge Functions → send-push → Secrets — вставь
   туда новую пару VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY из
   supabase/functions/send-push/README.md (замени старые значения).
3. На iPhone удали Bubbles с экрана Домой и добавь заново — старая
   подписка была создана под старым ключом и больше не годится.

Если ключи и так совпадали и проблема была в чём-то другом — в
supabase/functions/send-push/README.md теперь есть раздел с полным
чек-листом (задеплоена ли функция, подключены ли оба вебхука, что
смотреть в логах, и отдельный пункт про переключатель уведомлений
для Bubbles в настройках самого iPhone).

Причина, почему в реальном времени переставало приходить что угодно
(сообщения, лайки, заявки в друзья) и помогало только обновление

"pageshow", а не обычная перезагрузка страницы) все каналы реального

в 45 секунд на случай, если ни одно из событий не сработало. Просто
обнови файлы на хостинге — SQL менять не нужно.

ИСПРАВЛЕНО — ПУШ-УВЕДОМЛЕНИЯ НАКОНЕЦ РАБОТАЮТ (в т.ч. на iPhone)

Причина, почему уведомления не включались вообще ни у кого: файл
sw.js (service worker, без него push физически невозможен) лежал в
папке js/, а код регистрировал его по адресу ./sw.js — в корне
сайта. Браузер не находил файл там, где его ждали, регистрация
падала, и "Включить уведомления" никогда по-настоящему не работало —
без единой явной ошибки на экране.

Теперь sw.js лежит в корне проекта, рядом с index.html — именно там,
где его ждёт js/app.js. Заодно:
- добавлены iOS-теги (apple-mobile-web-app-capable и др.) в
  index.html — без них "На экран Домой" на iPhone открывает сайт как
  обычную вкладку Safari, а не отдельное приложение, а Web Push на
  iPhone работает ТОЛЬКО из приложения на экране Домой;
- запрос разрешения на уведомления (Notification.requestPermission)
  теперь происходит первым действием по нажатию кнопки, без единого
  await перед ним — Safari молча игнорирует этот запрос, если между
  нажатием и запросом происходит любая асинхронная задержка.

ЧТО СДЕЛАТЬ ПОСЛЕ ОБНОВЛЕНИЯ:
1. Залей ВСЮ папку заново на хостинг — важно, что sw.js теперь
   лежит рядом с index.html, а не в js/.
2. На iPhone удали Bubbles с экрана Домой, если уже добавлял(а)
   раньше, и добавь заново (Safari → Поделиться → На экран Домой) —
   старая иконка могла закешировать сломанную версию.
3. Открой добавленное приложение (не Safari-вкладку) и нажми
   "Включить уведомления" в Настройках.

ВАЖНО — ИСПРАВЛЕНИЕ ЛАЙКОВ (обязательно запусти SQL заново!)

Нашли причину, почему лайк от автора поста оставался, а лайк от
другого человека пропадал: в базе было правило, разрешающее менять
пост (а значит и список лайков внутри него) только автору поста.
Когда лайкал кто-то другой, запись тихо не сохранялась.

Лайки теперь хранятся в отдельной таблице post_likes, где каждый
может добавить/убрать только свою собственную запись — так это
работает у всех, а не только у автора. Просто открой Supabase ->
SQL Editor и запусти supabase.sql ещё раз (это добавит новую
таблицу и перенесёт туда все лайки, которые уже есть, — ничего не
потеряется). Затем обнови файлы index.html, css/style.css и
js/app.js на хостинге.

СТРУКТУРА
index.html                 главная страница
css/style.css              текущий дизайн bubbles
js/supabase-config.js      URL + ключ проекта Supabase
js/supabase.js              создание Supabase client

ПОДКЛЮЧЕНИЕ
1. Открой Supabase -> SQL Editor.
2. Вставь весь supabase.sql и нажми Run.
3. Открой Project Settings -> API.
4. Скопируй Project URL и Publishable/Anon key.
5. В js/supabase-config.js замени:
   YOUR_PROJECT_REF
   YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
6. Загружай всю папку на хостинг.

РЕГИСТРАЦИЯ
Теперь используется Supabase Auth по почте + паролю.
Если в Authentication включено подтверждение email, после регистрации нужно подтвердить письмо.

МУЗЫКА
Музыка больше не хранится в IndexedDB браузера.
MP3 и обложки загружаются в Storage bucket "music".
При публикации вводятся:
- название трека
- имя артиста
- обложка
- MP3

После публикации трек сразу появляется во вкладке «Музыка».
Глобальный плеер остаётся доступен при навигации по сайту.
