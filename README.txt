BUBBLES — Supabase version

НОВОЕ — РЕАКЦИИ НА СООБЩЕНИЯ (запусти supabase.sql заново)

Под каждым сообщением в чате теперь есть кнопка 🙂 — короткий выбор
из 5 эмодзи (❤️ 😂 👍 😮 😢). Реакция появляется под пузырьком у
обеих сторон переписки в реальном времени, без перезагрузки страницы.
Нажать свою же реакцию ещё раз — снять её; выбрать другую — заменить.

Добавлена новая таблица message_reactions (одна строка на пару
"сообщение+человек", как уже сделано для лайков постов), так что
и отправитель, и получатель могут ставить/снимать реакции — это не
требует правки самого сообщения, которую разрешено делать только
автору. Открой Supabase -> SQL Editor и запусти supabase.sql ещё
раз (ничего не удалит, только добавит новую таблицу и политики).
Затем обнови index.html, css/style.css и js/app.js на хостинге.

   следующий трек» растягивался в широкую полосу из-за общего
   стиля для всех полей ввода.

ВАЖНО — ИСПРАВЛЕНИЕ ЛАЙКОВ (обязательно запусти SQL заново!)

Нашли причину, почему лайк от автора поста оставался, а лайк от
другого человека пропадал: в базе было правило, разрешающее менять
пост (а значит и список лайков внутри него) только автору поста.
Когда лайкал кто-то другой, запись тихо не сохранялась.

Лайки теперь хранятся в отдельной таблице post_likes, где каждый
может добавить/убрать только свою собственную запись — так это
работает у всех, а не только у автора. Просто открой Supabase ->
SQL Editor и запусти supabase.sql ещё раз (это добавит новую
таблицу и перенесёт туда все лайки, которые уже есть, — ничего не
потеряется). Затем обнови файлы index.html, css/style.css и
js/app.js на хостинге.

ЧТО НОВОГО В ЭТОЙ ВЕРСИИ

1. supabase.sql — обязательно перезапусти в SQL Editor!
   Добавлена таблица friend_requests (заявки в друзья) и колонка
   read_at в messages (без неё «прочитано» не работало вообще).
   Файл безопасно перезапускать поверх старой базы — ничего не удалит.

2. Друзья — теперь через заявки.
   Кнопка "Добавить в друзья" отправляет заявку, а не добавляет
   сразу. На странице «Друзья» появились разделы «Заявки» и
   «Отправленные заявки», плюс бейдж на кнопке в меню.

3. Сообщения — теперь по-настоящему как в мессенджере.
   Новые сообщения появляются без обновления страницы, есть
   индикатор "печатает…", галочки ✓/✓✓ (отправлено/прочитано) и
   статус "онлайн" прямо в шапке чата.

4. Посты — лайк и комментарий больше не перерисовывают всю ленту.
   Обновляется только сам пост, так что страница больше не
   "прыгает" при лайке.

5. Музыка — вкладки «Моя музыка» / «Вся музыка», поиск по
   названию/артисту/автору, и трек теперь сам переключается на
   следующий по окончании (можно выключить переключателем).
   Добавлены кнопки ⏮️/⏭️ в плеере.

Старые файлы js/realtime.js, js/social-realtime.js и js/online.js
удалены — это были черновые дубли, которые плохо работали. Вся их
логика теперь аккуратно живёт внутри js/app.js.

СТРУКТУРА
index.html                 главная страница
css/style.css              текущий дизайн bubbles
js/supabase-config.js      URL + ключ проекта Supabase
js/supabase.js              создание Supabase client
js/app.js                   логика приложения
supabase.sql                таблицы, RLS и Storage bucket

ПОДКЛЮЧЕНИЕ
1. Открой Supabase -> SQL Editor.
2. Вставь весь supabase.sql и нажми Run.
3. Открой Project Settings -> API.
4. Скопируй Project URL и Publishable/Anon key.
5. В js/supabase-config.js замени:
   YOUR_PROJECT_REF
   YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
6. Загружай всю папку на хостинг.

РЕГИСТРАЦИЯ
Теперь используется Supabase Auth по почте + паролю.
Если в Authentication включено подтверждение email, после регистрации нужно подтвердить письмо.

МУЗЫКА
Музыка больше не хранится в IndexedDB браузера.
MP3 и обложки загружаются в Storage bucket "music".
При публикации вводятся:
- название трека
- имя артиста
- обложка
- MP3

После публикации трек сразу появляется во вкладке «Музыка».
Глобальный плеер остаётся доступен при навигации по сайту.
